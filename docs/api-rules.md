# 엔드포인트별 규칙

← [그룹 가계부](README.md) · 관련 [API 문서 읽는 법](api-docs.md) [인증과 그룹 격리](auth-and-scoping.md)

경로·스키마는 `/docs`에서 본다. 여기엔 **자동 문서가 표현 못 하는 규칙**만 적는다.

# 공통

- 인증이 필요한 모든 엔드포인트는 `Authorization: Bearer <JWT>`
- 인증 실패는 전부 **401**. 관리자 키 실패만 **403**
- **모든 응답은 호출자의 그룹으로 한정된다** → [인증과 그룹 격리](auth-and-scoping.md)
- 검증 실패는 FastAPI가 자동으로 **422**

# `/api/auth`

## `POST /login`
- 인증 불필요. **10회/분** (IP 기준), 초과 시 429
- 잘못된 초대 코드 → **401**
- 응답에 `id`가 아니라 **`user_id`**가 온다. 프론트 타입이 이걸 틀렸던 적이 있다
- 성공 시 프론트가 `setToken()`으로 localStorage + 쿠키에 저장한다

## `GET /me`
- 토큰의 `sub`로 사용자를 다시 조회해 반환한다. 여기는 `user_id`가 아니라 **`id`**로 온다
- 설정·통계 화면이 "지금 이 토큰이 누구인가" 를 서버에 되묻는 데 쓴다. `localStorage` 의
  사본이 아니라 **서버 판단**이 필요한 자리다
- `is_group_admin` 이 함께 온다. 화면이 카테고리 관리 영역을 보여줄지 가르는 값이고,
  **권한 판단 자체는 서버가 다시 한다** → [거래 등록 흐름](flow-create-transaction.md)

# `/api/transactions`

## `GET ""`
- **그룹 전체**의 거래를 반환한다. 읽기는 좁히지 않는다 — 공동 가계부의 핵심 기능이다
- `month` 쿼리(`YYYY-MM`)로 필터. **`date.startswith(month)` 방식**이라 형식이 어긋나면 조용히 안 잡힌다
- `month`를 안 주면 그룹의 **전체 거래**를 반환한다. 페이지네이션이 없다
- `date DESC` 정렬
- 카테고리·사용자를 `joinedload`로 함께 가져와 `category_name`, `category_icon`, `category_color`, `user_display_name`을 평평하게 실어준다

## `POST ""` → 201
- `group_id`, `user_id`는 **토큰에서 채운다.** 요청 본문에 넣어도 무시된다
- 카테고리가 없으면 **404**
- 카테고리가 **호출자의 그룹이 쓸 수 있는 것**이어야 한다 (시스템 기본값 또는 자기 그룹 전용). 아니면 **404**
- `type`은 `income`/`expense`만, `amount`는 **양수만**, `date`는 `YYYY-MM-DD`만 받는다. 어긋나면 **422**
- `account_id` 는 선택이다. 주면 **이 그룹의 계좌**여야 한다 — 아니면 **404**.
  주인이 아니어도 된다 (배우자의 대출을 대신 갚는 경우 → [계좌](accounts.md))
- ⚠️ **`type` 이 `income` 이면 계좌에 연결할 수 없다 (422).** 잔액 계산이 부호를 보지 않아서
  수입이 빚을 깎는다 → [계좌](accounts.md)
- `interest_amount` 는 `amount` 중 이자분이다. **계좌 없이 주면 422**, `amount` 보다 크면 **422**

## `PUT /{tx_id}`
- **자기가 쓴 내역만** 수정할 수 있다
- 같은 그룹 다른 구성원의 것 → **403** (목록에 이미 보이므로 숨길 게 없다)
- 다른 그룹 것 → **404** (목록에 안 보이므로 존재를 숨긴다)
- `exclude_unset=True`라 **보낸 필드만** 바뀐다
- `category_id`를 바꿀 때도 POST와 **동일한 소유권 검증**을 거친다. 아니면 **404**
- 계좌·이자 검증은 **저장 뒤의 상태**로 본다. 금액만 줄여도 이자분이 그보다 커질 수 있다

## `DELETE /{tx_id}` → 204
- **자기가 쓴 내역만** 삭제할 수 있다. 동료 것은 403, 다른 그룹 것은 404
- 실제 삭제다. 소프트 삭제가 아니다
- 프론트는 4초 지연 후 호출한다 → [삭제와 되돌리기](flow-delete-undo.md)

# `/api/categories`

## `GET ""`
- **시스템 기본값 + 내 그룹 전용**을 함께 반환한다 (`group_id IS NULL OR group_id = 내 그룹`)
- `type`, `name` 순 정렬
- `기타`가 expense·income 양쪽에 있으므로 **`name`만으로 찾으면 안 된다** → [거래 등록 흐름](flow-create-transaction.md)

## `POST ""` → 201
- **그룹 관리자만.** 아니면 **403** (그룹 관리자 = 그 그룹의 최초 초대 사용자)
- 받는 것은 `type`·`name`·`icon` 뿐이다. **`color` 는 서버가 배정한다** — 사용자가 고르면
  대비·채도 검증을 통과 못 하는 값이 들어온다 → [통계 집계 규칙](stats-rules.md)
- 이름이 비면 **422**, 같은 `type` 에 이미 보이는 이름이면 **409**
- 중복 검사 기준은 **보이는 카테고리 전부**(시스템 기본값 포함)다. 기본값과 같은 이름을
  그룹이 또 만들면 선택 목록에 같은 이름이 두 개 뜬다

## `DELETE /{category_id}` → 204
- **그룹 관리자만.** 그리고 **자기 그룹 것만** — 시스템 기본값이나 남의 그룹 것은 **404**
- **거래는 지우지 않고 `기타` 로 옮긴다.** 적요가 남아 어떤 지출이었는지는 알 수 있다 (#41)
- 옮겨 둘 `기타` 가 없으면 **409**

시스템 기본 카테고리(`group_id IS NULL`)는 여기가 아니라 `/api/admin/categories` 에서
전체 관리자가 다룬다.

# `/api/stats`

집계 규칙 전반은 [통계 집계 규칙](stats-rules.md)에 정리했다.

## `GET /summary`
- `month` **필수**, `user_only` 선택(기본 false)
- `income`, `expense`, `balance`(= income − expense)
- `MainView` 의 요약 카드가 이 값을 쓴다. **클라이언트가 목록을 더해 내지 않는다** — 목록에
  페이지네이션이 들어가는 순간 조용히 틀려지기 때문 (#14) → [통계 집계 규칙](stats-rules.md)

## `GET /categories`
- `month` 필수, `user_only` 선택
- ⚠️ **지출만 집계한다.** 수입은 포함되지 않는다
- 금액 내림차순 정렬, `percentage` 포함

## `GET /daily`
- `month` **필수**, `user_only` 선택
- 그 달의 **날짜별 수입·지출 소계**. `substr` 없이 `date` 로 그대로 `GROUP BY` 한다 (쿼리 1회)
- ⚠️ **거래가 없는 날은 응답에 없다.** 달력의 빈 칸을 채우는 일은 화면 몫이다
- 수입·지출 양쪽 다 낸다 (카테고리·구성원 통계와 달리 지출만이 아니다)

## `GET /trend`
- 파라미터 없음. **항상 최근 6개월** (이번 달 포함)
- `user_only`가 없다 — 언제나 그룹 전체
- `substr(date, 1, 7)` 로 묶어 **쿼리 한 번**이다. 거래가 없는 달의 빈자리는 파이썬이 채운다

## `GET /members`
- `month` 필수
- ⚠️ **지출만** 집계
- INNER JOIN이라 **지출이 0인 구성원은 아예 나오지 않는다**

# `/api/accounts`

대출·예금·적금. 규칙 전반은 [대출·예금·적금 계좌](accounts.md)에 있다.

## 공통
- **소유는 개인, 열람은 그룹.** 거래와 같은 규칙이다 → [인증과 그룹 격리](auth-and-scoping.md)
- ⚠️ **응답의 `balance`·`paid_principal`·`paid_interest` 는 저장된 값이 아니다.** 연결된
  거래에서 매번 계산해 실어준다
- `amount` 의 뜻은 `kind` 가 정한다 — 대출: 원금 · 예금: 예치액 · **적금: 월 납입액**
- `category_id` 는 상환·납입 내역에 기본으로 붙일 카테고리다. **지출 카테고리만** 받는다 —
  아니거나 남의 그룹 것이면 **404**. 비워도 된다

## `GET ""`
- **그룹 전체**의 계좌. 동료 것도 보인다
- `kind` 쿼리로 거를 수 있다 (`loan` / `deposit` / `installment`)
- 정렬은 `status`, `matures_on` 순 — 진행 중인 것이 먼저, 만기가 가까운 것이 위다

## `POST ""` → 201
- **주인은 만든 사람**이다. 본문으로 지정할 수 없다
- 만기일이 시작일보다 빠르면 **422**
- ⚠️ 대출이 아닌데 `repay_method` 를 주면 **조용히 지워진다.** 예금에 "원리금균등" 이 붙어
  있으면 화면이 그걸 믿고 상환 계산을 시도한다

## `PUT /{account_id}`
- **주인만.** 동료 것은 **403**, 다른 그룹 것은 **404** (거래와 같은 방침)
- `kind` 는 받지 않는다 — 바꾸면 `amount` 의 뜻과 잔액 계산식이 통째로 달라진다

## `DELETE /{account_id}` → 204
- **주인만**
- ⚠️ **거래는 지우지 않고 연결만 끊는다** (`account_id`·`interest_amount` → NULL).
  실제로 돈이 오간 기록이다

## `POST /{account_id}/settle`
- **주인만.** 이미 끝난 계좌면 **409**
- `settled_amount` 는 **사람이 확정한 값**이다. 서버가 계산하지 않는다
- 예적금이면 확정액에서 넣은 원금을 뺀 만큼을 **이자 수입 거래로 만든다.** 그 거래의 주인은
  정산을 누른 사람이 아니라 **계좌 주인**이다
- `interest_category_id` 를 안 주면 `금융수입` → `기타`(수입) 순으로 서버가 고른다.
  수입 카테고리가 하나도 없으면 **409**
- ⚠️ 지출 카테고리를 주면 **404** — 이자는 수입이고, 지출로 잡으면 통계가 뒤집힌다
- 대출은 거래를 만들지 않는다. 끝났다는 사실만 기록한다

# `/api/admin`

관리자 키가 유일한 보호 수단이다. 전 라우트 **10회/분**. 화면 쪽 설명은
[관리자 화면](admin-console.md)에 있다.

## 공통
- 신원은 두 갈래로 받는다 (`resolve_admin`)
  - `X-Admin-Key` 헤더에 `ADMIN_KEY` 원문 — **전체 관리자만.** curl·스크립트용이다
  - `Authorization: Bearer` **관리자 토큰** — `scope` 로 전체(`admin`)/그룹(`group_admin`)이 갈린다
- 어느 쪽도 통과 못 하면 **403**. 권한이 모자라면 역시 **403**
  (`전체 관리자만 할 수 있습니다.` / `이 그룹을 관리할 권한이 없습니다.`)
- 그룹 관리자 인증키(`groups.admin_code`) **원문은 헤더로 받지 않는다.** 로그인에서만 쓰이고
  그 자리에서 토큰이 된다
- 키 검사는 `Depends`가 아니라 **함수 본문 안에서** 한다. rate limit이 동작하려면 그래야 한다 → [인증과 그룹 격리](auth-and-scoping.md)
- 관리자 토큰으로 **사용자 API 는 못 부른다** (`get_current_user` 가 `scope` 를 보고 401).
  반대로 사용자 토큰으로 관리자 API 도 못 부른다

## `POST /login`
- 인증 불필요. `{"admin_key": "..."}` 하나만 받는다
- `ADMIN_KEY` 와 같으면 **전체 관리자 토큰**, 어느 그룹의 `admin_code` 와 같으면 그 그룹의
  **그룹 관리자 토큰**. 둘 다 아니면 **403**
- 비활성 그룹의 옛 인증키로 들어오면 **403**
- 그룹 관리자 토큰에는 `group_id`·`group_name` 이 함께 실린다. 화면이 "나는 누구인가" 를
  **토큰 하나에서** 읽게 하려는 것이다 — 권한과 표시를 따로 저장하면 둘이 어긋난다
- 수명은 `ADMIN_TOKEN_EXPIRE_MINUTES`(기본 60분)

## 그룹

| 엔드포인트 | 누가 | 하는 일 |
|---|---|---|
| `POST /groups` → 201 | 전체 관리자 | 그룹 생성. **`admin_code` 도 함께 발급된다** |
| `GET /groups` | 둘 다 | 그룹 관리자에게는 **자기 그룹 한 개만** 보인다 |
| `POST /groups/{id}/deactivate` | 전체 관리자만 | 비활성화 |
| `POST /groups/{id}/restore` | 전체 관리자만 | 복구 |
| `POST /groups/{id}/admin-code` | 전체 관리자만 | 그룹 인증키 재발급 |

- `DELETE` 가 없다. 비활성화는 `deactivated_at` 을 채울 뿐이고 **행도 거래도 카테고리도
  그대로 남는다** → [데이터 모델](data-model.md)
- 비활성화하면 그 그룹의 **인증키가 전부 무효**가 된다 (구성원 `invite_code` + `admin_code`).
  **복구해도 살아나지 않는다** — "전부 무효화" 가 말이 되려면 그래야 한다
- 이미 로그인한 세션도 다음 요청에서 끊긴다 (`get_current_user` 가 그룹 상태를 본다).
  로그인만 막으면 최대 30일짜리 토큰이 살아 있다
- 응답의 `admin_code` 는 **전체 관리자에게만** 실린다. 그룹 관리자가 자기 키를 다시 읽을 수
  있으면 그 화면을 한 번 본 사람이 영구 접근권을 갖는다
- 없는 그룹은 **404**

## 구성원

| 엔드포인트 | 누가 | 하는 일 |
|---|---|---|
| `POST /users` → 201 | 둘 다 (자기 그룹만) | 구성원 추가 |
| `GET /users` | 둘 다 (자기 그룹만) | 목록 |
| `POST /users/{id}/invite-code` | 둘 다 (자기 그룹만) | 초대 코드 재발급 |

- `POST /users` — 없는 그룹이면 **404**, 비활성 그룹이면 **409**, 코드가 이미 쓰이면 **409**
- `invite_code` 를 안 주면 `secrets.token_urlsafe(8)` 로 생성한다. 응답에 실려 온다 —
  **이 값이 곧 비밀번호다**
- **그룹 관리자는 최초 구성원 한 명으로 정해진다.** `groups.admin_user_id` 가 비어 있을 때만
  채워지므로 뒤에 들어온 사람이 조용히 관리자가 되지 않는다
- `GET /users` 는 `invite_code` 를 평문으로 낸다. 재발급 말고는 알려줄 방법이 없어서다.
  그룹 관리자에게는 `group_id` 쿼리로 남의 그룹을 지목해도 **자기 그룹만** 나온다
- 재발급하면 예전 코드는 즉시 못 쓴다. 다만 **이미 나간 JWT 는 만료까지 산다** — 폐기 목록이
  없다 → [인증과 그룹 격리](auth-and-scoping.md)

## 공통 카테고리 — `/categories`

`group_id IS NULL` 인 카테고리다. **전체 관리자만** 만진다.

- `GET` / `POST` → 201 / `DELETE /{id}` → 204
- 색은 그룹 카테고리와 같은 규칙으로 서버가 배정한다 (`palette.next_color`)
- 이름 중복은 **409**, 빈 이름은 **422**, 그룹 전용 카테고리를 여기서 지우려 하면 **404**
- ⚠️ **`기타` 는 지울 수 없다 (409).** 다른 카테고리를 지울 때 옮겨 둘 자리다 — 이걸 지우면
  그 뒤로 어떤 카테고리도 못 지운다
- ⚠️ 하나를 지우면 그것을 쓰던 **모든 그룹**의 거래가 `기타` 로 옮겨간다. 그룹 카테고리
  삭제와 같은 방침이되 영향 범위가 전부다
