# 목록 정렬과 필터

← [그룹 가계부](README.md) · 관련 [거래 등록·수정 흐름](flow-create-transaction.md) [삭제와 되돌리기](flow-delete-undo.md)

홈 목록의 정렬·필터는 **전부 클라이언트에서 한다.** 서버에 파라미터를 더 보내지 않는다.

# 왜 클라이언트인가

목록은 이미 **한 달치를 통째로** 받아온다 (`GET /api/transactions?month=YYYY-MM`).
한 달 거래는 많아야 수백 건이라, 걸러 보자고 매번 왕복할 이유가 없다.
필터를 바꿀 때마다 스피너가 도는 것보다 즉시 반응하는 쪽이 낫다.

건수가 커져 이 전제가 깨지면 그때 서버 쿼리로 내린다.

# 정렬

두 가지뿐이다 — **최신순**(기본)과 **오래된순**. 헤더 오른쪽 버튼으로 토글한다.

정렬 키는 `date` 하나가 아니라 `` `${date} ${created_at}` `` 이다.

```ts
const key = (t: Transaction) => `${t.date} ${t.created_at ?? ''}`;
```

## 왜 `created_at` 이 필요한가

`date` 는 **사용자가 고른 날짜**고 하루 단위다. 오늘 세 건을 넣으면 셋 다 `date` 가 같아서,
`date` 만으로 정렬하면 **그 안의 순서가 서버가 준 순서에 맡겨진다.** 백엔드는
`order_by(date.desc())` 만 하고 2차 키가 없으므로, 방금 적은 항목이 목록 어디에 있는지
알 수 없다. `created_at` 을 2차 키로 쓰면 **마지막에 넣은 것이 그 날짜 안에서 맨 위**로 온다.

둘 다 ISO 문자열(`2026-08-27`, `2026-08-27T07:41:43`)이라 문자열 비교로 시간순이 맞는다.

> [!NOTE]
> `created_at` 은 **초 단위**다. 같은 초에 들어간 두 건은 순서를 가르지 못한다.
> 사람이 손으로 넣는 속도에서는 문제가 안 되지만, 스크립트로 밀어 넣을 때는 겹친다.

날짜 그룹 헤더의 순서도 같은 방향을 따른다. 그룹 안 항목은 이미 정렬된 배열을 순서대로
담기만 하므로 따로 정렬하지 않는다.

# 필터

| 필터 | 값 | 비교 대상 |
|---|---|---|
| 종류 | `all` / `income` / `expense` | `t.type` |
| 카테고리 | `all` / `category_id` | `t.category_id` |

카테고리는 **이름이 아니라 id 로 비교한다.** 시스템 카테고리에 `기타` 가 수입·지출 양쪽에
있어서 (→ [데이터 모델](data-model.md)) 이름으로 거르면 둘이 섞인다.

## 두 필터는 서로를 좁힌다

종류를 고르면 카테고리 드롭다운도 그 종류의 것만 남는다. 지출을 보면서 `급여` 를 고를 수
있으면 결과가 항상 0건이라 고장처럼 보인다.

이미 카테고리를 골라둔 상태에서 종류를 바꾸면 **고른 카테고리가 새 종류에 없을 때 자동으로
풀린다.** 안 그러면 화면에는 조건이 남아 있는데 목록만 텅 비고, 왜 비었는지 알 수 없다.

## 합계는 보이는 것만 더한다

요약 카드는 **필터를 통과한 항목만** 더한다. 필터를 걸었는데 합계가 그대로면 무엇을 더한
숫자인지 알 수 없기 때문이다. 필터가 걸려 있으면 카드 문구도 `이번 달 잔액` 에서
`선택한 내역 합계` 로 바뀐다.

## 빈 화면은 두 종류다

- **아직 내역이 없습니다** — 이 달에 거래가 0건
- **조건에 맞는 내역이 없습니다** — 거래는 있는데 필터가 다 걸렀다. 이때만 [필터 초기화] 를 준다

# 삭제·되돌리기와의 관계

`handleDelete` 는 **필터된 목록이 아니라 원본 `transactions` 배열**에서 index 를 찾는다.
되돌리기가 원래 자리에 다시 꽂아야 하는데(→ [삭제와 되돌리기](flow-delete-undo.md)),
그 자리는 화면에 보이는 위치가 아니라 원본에서의 위치다.

# 월 선택기

`<input type="month">` 에 `required` 를 준다. 크롬 월 선택기의 **[삭제](지우기)** 버튼을
없애기 위해서다. 값을 비우면 `month` 파라미터가 빠져 **그 달이 아니라 전체 기간**이
조회된다 — 백엔드가 `if month:` 로만 거르기 때문이다. 화면은 여전히 "이번 달" 이라고
말하는데 내용은 전체가 되는, 조용히 틀리는 상태다.

`required` 를 모르는 브라우저를 대비해 `onChange` 에서도 빈 값을 무시한다.
